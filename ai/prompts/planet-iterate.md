# 提示词模板：改进 planet 实验（AI 驱动迭代）

用途：把这个模板丢给任意能调用 Godot MCP 的 agent，让它按「改 → 跑检查 → 看截图」的
闭环去改进 `projects/planet/`。已经把本项目的验证手段写死在模板里，避免 agent
只会改代码、不会自证。

---

## 模板正文

```
你在改 E:\AI\AI2Godot\projects\planet/ —— Godot 4.7 + GDScript 的星球演化小游戏。

目标：<一句话描述要改什么，例如「让掠夺者在玩家进入恒星阶段后更激进」>

约束：
- 只用 GDScript，不引入插件、不改 project.godot 的渲染设置。
- 保持现有 dev 开关（--selftest / --selftest-long / --dirtest / --stage=N --shot）可用，
  这些开关是自动化验证的基础，删掉就等于让项目失明。
- 数值改动必须能解释清楚为什么是这个值，不要顺手「调平衡」。

必须走的闭环（按顺序）：
1. 先读相关文件（scripts/world.gd、scripts/rival.gd 等），不要凭印象改。
2. 改代码。
3. 跑 `python ai/scripts/run_checks.py --quick`（约 35 秒）确认没把核心循环改坏；
   涉及外观/镜头时跑完整版（含 6 个阶段截图，约 2 分钟）。
4. 打开 build/shots/ 里的截图，自己看图判断外观是否符合预期；
   不要只因为进程退出码 0 就说「渲染正常」。
5. 如果改了平衡性，必须跑 --selftest-long，报告 end/peak 质量与 stages 序列，
   并说明和上一版相比的变化是否在预期内。
6. 全部通过才允许 git commit；任何一步失败就停下来报告失败输出，不要绕过检查。

验收标准（不满足就是没做完）：
- dirtest 在 yaw=0/45/135/200 四个角度全部 PASS；
- selftest RESULT: PASS；
- 平衡改动：selftest-long 的 stages 覆盖到你关心的阶段；
- 相关截图肉眼确认无误。
```

## 常用变体

| 场景 | 「目标」怎么写 | 必跑的检查 |
|---|---|---|
| 改操作/镜头 | 「加入 Q/E 旋转视角」 | `--quick`（dirtest 覆盖四角度）+ 两角度截图对比 |
| 改平衡数值 | 「黑洞阈值 900 → 700」 | `--quick` + `--selftest-long` 前后对比 |
| 改外观/着色器 | 「恒星阶段更像恒星」 | 完整版（6 阶段截图）+ 逐图查看 |
| 加新机制 | 「掠夺者会结盟」 | 全部 + 用 `--show-rival` 截图确认 |

## 已知的坑

- `--shot` 需要真实渲染窗口，**不能加 `--headless`**；其余检查都该加 `--headless`。
- `--shot-path=` 可以是绝对路径、`res://`、`user://` 或相对路径（相对路径按**工程目录**
  解析，缺失的目录会自动创建）。
- 自测随机数默认固定种子 1729（`--seed=N` 可换）。比的是 `grew` / `stages` /
  `note=survived`，**不要**拿 `end mass` 的具体数值做前后对比 —— headless 帧间隔不固定，
  同一份代码 18 秒能跑出一两百也能跑出八百。
- 自测机器人会躲开能吞掉自己的掠夺者，所以它红了通常说明「连会躲的玩家都活不下来」，
  是平衡问题，不是机器人笨。
- 命令行自定义参数要在 `--` 之后：`godot --path . -- --selftest`。
- 游戏内的 dev 开关只在解析到对应参数时才 `set_process(true)`，正常运行不受影响。
