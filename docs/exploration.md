## 已跑通的闭环

### AI 自测闭环（dev 开关 + 一条命令跑批）
- 状态: 已跑通（planet 实验内）
- 目标: 让 AI 改完代码后能**自己验证**有没有改坏，而不是靠人打开游戏看
- 关键做法:
  - 游戏里内置 dev 开关，只在带命令行参数时激活：`--selftest`（18s 玩法）、
    `--selftest-long`（60s 平衡）、`--dirtest`（操作映射，`--yaw=N` 先转镜头再测）、
    `--stage=N --shot --shot-path=... --yaw --pitch`（定角度截图）
  - 逻辑检查一律 `--headless`；截图检查**不能** headless（要真实渲染上下文）
  - `ai/scripts/run_checks.py`（仅标准库）定位 Godot 可执行文件（`--godot` /
    `GODOT_PATH` / `.mcp.json`）、跑完 12 项检查、解析 `RESULT: PASS` 并汇总
- 踩过的坑:
  - `get_cmdline_user_args()` 只认 `--` 之后的参数；PowerShell 传参时不要把多个
    开关拼成一个字符串
  - `--shot-path` 给相对路径时 `save_png` 会 `err=7` 静默失败 → 现在按工程目录
    解析并自动建目录
  - GDScript 里没有 `NaN` 常量（要用标志位判断，或写 `NAN`）；
    `DirAccess.make_path_absolute()` 是 Godot 3 的 API，4.7 里不存在（连解析阶段就报错），
    改用 `ProjectSettings.globalize_path("res://")` 拼路径
  - 游戏脚本解析失败时进程不会退出，会一直挂着 → 手工跑加 `--quit-after 400` 兜底
  - **自测不加随机种子就是掷骰子**：未播种时掠夺者可能刷在玩家旁边，18s 自测会随机红
    （实测跑批里 12 项会随机变 11 项）。现在 `--selftest` 默认播种 1729，
    并让机器人会躲避捕食者；判定看 `grew`/`stages`/存活，不看 `end mass` 的具体数值
- 结论: 这套闭环是 AI 驱动开发的地基。实测 12/12 PASS 约 2 分钟；
  `--quick`（35 秒）足够覆盖「改代码有没有把核心循环/操作映射改坏」。
  下一步把同样的开关约定套进新实验：**任何新实验先写 dev 开关，再写玩法**。

### GDScript 代码辅助
- 状态: 已跑通（planet 实验内）
- 目标: AI 生成 GDScript 并能在 Godot 直接运行
- 关键问题: 类型安全、4.x 语法准确性、如何自动验证
- 结论: 已跑通「AI 改 GDScript → headless 自测 → 看截图」的循环，
  本轮相机环绕重构（`camera_rig.gd` + `dirtest.gd`）就是这条路径产出的。
  自动验证靠的是内置 dev 开关（见上一节），不是靠 AI 自己读日志。
  语法坑（4.7）：`NaN` 常量不存在、`DirAccess` 静态/实例方法划分与 3.x 不同、
  类型推断失败会直接连累整个脚本加载 —— 所以每个改动都要跑 `--quick`。
  提示词模板见 `ai/prompts/planet-iterate.md`。
